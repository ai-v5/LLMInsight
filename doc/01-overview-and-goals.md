# 01 · 总览与目标

> 背景动机、现有工具盲区、差异化定位，以及亮点 / 基础 / 多卡三层目标。

## 1.1 这是什么

**LLMInsight** 是一个面向**昇腾（Ascend）NPU 大模型训练**的 Profiling 与性能洞察平台。它把一份 `ASCEND_PROFILER_OUTPUT`（torch_npu / MindSpeed-LLM 采集）目录，**零配置**地解析为统一数据模型，派生性能指标，运行规则引擎，并通过一个无构建的 Web 仪表盘呈现「**现象 → 根因 → 建议 → 预计收益 → 置信度**」式的可执行洞察。

当前样例对象是 **DeepSeek-V3 结构 MoE 模型**（MLA + 128 专家、EP64）的**单卡（device 0）、单 step（step5）**训练采集。

## 1.2 为什么需要它（现有工具的盲区）

昇腾 MindStudio Insight、msprof-analyze、TensorBoard、Perfetto 等能看时间线 / 算子，但普遍存在五个短板：

| # | 盲区 | 后果 |
|---|---|---|
| ① | **一次性快照** | 缺整个训练过程的时间演化视角，看不出「第几步开始变慢」 |
| ② | **只给图、不给结论** | 需要资深性能专家手工解读 trace，门槛极高 |
| ③ | **停在底层算子层** | 不懂模型结构语义，回答不了「是 MoE 分发慢还是 Attention 慢」 |
| ④ | **不报优化空间** | 没有理论上界、没有 What-if，不知道「改了能省多少、值不值得优化」 |
| ⑤ | **采集可能被扭曲却无人提示** | 如 `ASCEND_LAUNCH_BLOCKING=1` 放大同步开销，据错图下错结论 |

## 1.3 差异化定位

LLMInsight 以四大支柱与现有工具形成代差：

1. **LLM 自动分析诊断** —— 把「需要专家盯 trace」变成「问一句就有结论」。
2. **全训练回放式可视化** —— 像回放录像一样定位训练劣化的时刻。
3. **训练语义化归因** —— 把算子 / 通信归因到 MLA / MoE / Norm / Optimizer 等模型结构。
4. **开箱即用** —— 指向一个目录即自动解析 → 出图 → 出洞察。

## 1.5 基础目标（Baseline，单卡优先）

- **G1 一站式呈现**：8 个输出文件（含 104MB 时间线）解析为统一数据模型，单页可览、逐层下钻。
- **G2 自动诊断**：规则引擎 + LLM 自动定位 Top-N 瓶颈（计算 / 通信 / 访存 / 同步 / 负载）。
- **G3 单卡优先、架构预留多卡**：数据模型与视图按 `rank × step` 维度设计，rank 维度先留空接口。
- **G4 可复现 / 可分享**：诊断结论可导出，关键指标可作回归基线。

## 1.6 多卡 / 集群目标（专项 · 未来阶段）

> 当前仅单卡样例；以下为多卡 profiling 的独立专项目标，待多卡数据提供后启动。

- **M1 慢卡 / 掉队卡定位**：对比各 rank 的 step / 算子 / 通信耗时，找拖累集合通信的最慢 rank。
- **M2 负载均衡分析**：DP/EP 计算量方差；MoE 专家 token 负载不均、路由倾斜。
- **M3 跨 rank 通信矩阵**：`communication_matrix.json` → rank×rank 流量 / 带宽热力图。
- **M4 集合通信对齐**：同一集合通信里「谁先到 / 谁拖后」、等待跨 rank 归因。
- **M5 并行维度视角**：按 TP/PP/EP/DP 分组聚合，回答「哪个并行维度是瓶颈」。
